# Plan 4: natywne okno Win32, zasobnik, skróty, dźwięki, ustawienia — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The players' everyday client: a native Win32 window with rooms, people, chat and big Mute/Deafen buttons; a tray icon; global hotkeys that work while a game has focus; short confirmation sounds; a settings dialog stored as TOML in `%APPDATA%`.

**Architecture:** All behaviour lives in a pure, unit-tested `AppState` (client-core) that consumes `SessionEvent`s, user `Action`s and audio activity, and returns `Effect`s plus a view model. The Win32 layer (client-win `ui/`) only renders the view model, turns window messages into `Action`s and executes `Effect`s. The session runs on a background tokio runtime and wakes the UI thread with `PostMessageW(WM_APP_SESSION)`. The audio threads publish who is speaking and the mic level through lock-free tables the UI polls every 100 ms.

**Tech Stack:** Rust 2021, `windows` 0.62 (raw Win32: common controls v6, Shell_NotifyIconW, RegisterHotKey, PlaySoundW, clipboard, registry), `embed-resource` (new, build-time only, embeds the manifest), existing crates.

**Spec:** `docs/superpowers/specs/2026-10-28-komunikator-glosowy-design.md` — sections 2 (goals 1, 6, 9, 10), 4 (anti-goals), 6.4 (chat notifications), 6.6, 6.7 (client UI — the main source), 6.9 (first configuration).

## Global Constraints

- Native Win32 only: no WebView, no Electron, no browser, no immediate-mode GUI toolkit (spec 1, 4, 6.7).
- Global hotkeys only through `RegisterHotKey`; never `WH_KEYBOARD_LL`, never any hook, DLL injection or reading other processes; no overlays (spec 6.7).
- No toast notifications; new chat while minimised = short sound (can be turned off) + tray badge (spec 6.4).
- Closing the window minimises to tray; the tray menu has: Pokaż okno, Wycisz mikrofon, Wycisz wszystkich, Wyjdź; left click on the tray icon toggles mute (spec 6.7).
- Settings file: TOML in `%APPDATA%\komunikator\settings.toml`; volumes remembered by username (spec 6.7).
- High DPI (per-monitor v2) and multiple monitors; the window remembers position and size (spec 6.7).
- Client budget: < 30 MB RAM, < 1 % CPU while talking (spec 2.1); the UI must not redraw on a timer when nothing changed.
- All user-facing text in Polish with correct diacritics.
- Audio threads stay allocation- and lock-free in the hot path (spec 6.2).
- New dependency allowed: `embed-resource` (build-dependency of client-win). No other new crates.

## Review Focus

1. A hotkey already taken by another program → `RegisterHotKey` fails; the user sees a Polish message in the status bar and settings, not silence (Task 4 `hotkey_conflict_is_reported`; Task 6 shows it).
2. The settings file is corrupt or written by a newer version → the app starts with defaults, sets the bad file aside, and tells the user (Task 1 `broken_settings_are_set_aside`).
3. A chat message with several links → clicking the line copies the first link and the context menu offers each one (Task 2 `chat_line_links_are_offered`).
4. The game takes focus while someone talks for an hour → the speaking indicator and tray stay correct, the UI thread does no work when nothing changed (Task 2 `view_is_unchanged_without_events`).
5. The password must never be stored in the clear (Task 1 `password_is_stored_protected`).

### Task 3: Audio engine with activity and level

**Files:** Create `crates/client-core/src/audio/activity.rs`; Modify `crates/client-core/src/audio/mod.rs`, `crates/client-win/src/pipeline.rs`; Create `crates/client-win/src/engine.rs`; Modify `crates/client-win/src/lib.rs`, `crates/client-win/src/main.rs`.

**Interfaces:**
- Produces:
  - `pub struct Activity` (client-core): 32 fixed slots of `(AtomicU16 id, AtomicU32 last_frame)` plus `AtomicU32 frame`, `AtomicBool me_speaking`, `AtomicU32 mic_level_bits` (f32 dBFS). Writers: render (`heard(id)` for each voice that produced audio this frame, `tick()` once per frame), capture (`set_me(speaking, level_dbfs)`). Reader: `speaking(&self, out: &mut Vec<MemberId>)` — ids heard within the last 15 frames (300 ms); `me_speaking()`; `mic_level_dbfs()`. Writers never lock or allocate; a full table overwrites the stalest slot.
  - `render_loop(sink, inp, controls, gains, activity: Arc<Activity>, stop)`; `capture_loop(src, vad, enc, out, controls, activity: Arc<Activity>, sensitivity: Arc<AtomicU32> /* f32 bits */, stop)` — capture applies a changed sensitivity with `Vad::set_sensitivity` between frames.
  - `pub struct AudioEngine` (client-win, Windows): `start(capture: Option<String>, render: Option<String>, sensitivity: f32, audio_out, audio_in, controls, gains, activity) -> AudioEngine`, `set_sensitivity(&self, s: f32)`, `restart_devices(&mut self, capture: Option<String>, render: Option<String>)` (stops and joins both threads and reopens with the new ids; the session channels survive — the render thread returns its `audio_in` receiver when it stops), `stop(self)`. The CLI uses it too.

A 100 ms timer reads `Activity` into `on_activity` and repaints only on change. Session events arrive through an `std::sync::mpsc` channel plus `PostMessageW(hwnd, WM_APP_SESSION)` from a forwarding task. `Effect`s run here (`SetGain`/`ClearGains` → `GainTable`, `PlaySound` → `ui::sound`, `CopyToClipboard`, `SaveSettings`, `Trust` → `KnownDevices::verify/accept` + `SessionCommand::TrustChanged`). The window rect is restored if it intersects a monitor (`MonitorFromRect`, `MONITOR_DEFAULTTONULL`), else centred on the primary monitor. `WM_DPICHANGED` applies the suggested rect and re-creates fonts. If `run_as_admin` is set and the process is not elevated: `relaunch_as_admin()` and exit. If settings are not configured, the first-run dialog (Task 6) opens before the session starts; until Task 6 lands, an unconfigured start shows a message box `Brak konfiguracji` and exits.
